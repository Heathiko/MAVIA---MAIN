## 1. What MAVIA is

An adaptive, audio-tactile science tutoring platform for **blind and
low-vision elementary learners** (undergraduate thesis project, Philippines).
A teacher uploads science PDFs; the system extracts the lesson, builds
teachable concepts, writes simplified and elaborated versions of each concept,
generates a question bank, converts everything to speech, derives a
prerequisite graph, and publishes a course a learner can listen through.

**Accessibility is the product, not a feature.** A silent audio track, a
figure description that reads out the model's own chatter, or a control a
screen reader cannot reach are functional defects, not polish.

### Who owns what

| Area | Owner |
|---|---|
| PDF extraction, content generation, figure descriptions | a groupmate (not the user) |
| Question + answer generation | the user |
| Grouping, content versions, learning path, publishing | shared; the user drives it |
| Learner-facing mobile app / adaptive serving | a groupmate |

The user has asked for changes inside the groupmate's files before (the figure
prompt, 2026-09-21). That is their call; say whose file you are touching.

### Tech stack

- Backend: Django 5.2 + DRF, SQLite (`backend/db.sqlite3`), apps: `lessons`,
  `course`, `learning_path`, `question_generation`, `adaptive`, `user`.
- Local models via **Ollama**: Gemma for content versions and question
  generation, a vision model for figure descriptions. A pinned
  **sentence-transformers** pair (all-MiniLM-L6-v2 + cross-encoder
  stsb-roberta-base) for grouping and for the learning path.
- TTS: Edge TTS (needs network access to `speech.platform.bing.com`).
- Frontend: React 18 + Vite in `frontend/`. **`frontend/src/styles/pipeline.css`
  is the imported stylesheet; `frontend/src/index.css` is a near-duplicate that
  is not imported** — the codebase mirrors CSS into both. There is **no
  frontend test runner at all**.

### Running things

```bash
cd backend && python manage.py test -v 1      # 796 tests, all passing at HEAD
cd frontend && npm run build                  # must stay clean; do not commit frontend/dist
```

System `python` (no venv). Shell is Git Bash on Windows.

## 2. The pipeline, end to end

1. **Upload + extraction** — a PDF becomes an ordered list of
   `LearningObject` rows (title, the section heading it sat under, content,
   order). Figures become objects whose content is written by a vision model.
   The teacher confirms the objects per file.
2. **Grouping → concepts** — objects that teach the same thing across
   different PDFs are put in one `LearningObjectGroup`. **A group is a
   concept, and a concept is one step of the learning path.**
3. **Versions** — one PDF supplies the **Normal** version; each other PDF's
   contribution is classified Simplified / Elaborated / Extra; anything missing
   is generated by Gemma.
4. **Questions** — a bank per concept, generated from its Normal text.
5. **Audio** — Edge TTS per object; a version plays its objects' clips in order.
6. **Publishing** — a completeness gate, then audio, then the learning path is
   derived and saved as `LearningPathStep` rows.
7. **Adaptive serving** — BKT + DQN are described in the manuscript but **do
   not exist in the codebase yet**. Do not assume they are there.

## 3. Concept bundles (the current model)

The central idea, introduced 2026-09-20, replacing a manual "merge" step.

Two PDFs chunk the same lesson at different grain: one teaches Solid in a
single passage, the other as a section plus a particle diagram plus an examples
list. A concept therefore holds a **bundle per PDF**: an ordered list of that
PDF's objects.

```
bundles_for_group(group) -> {material_id: [LearningObject, ...]}   # ordered by (order, id)
```

`backend/lessons/services/concept_bundles.py` is the **only** authority for
that ordering. Version assignment, audio, questions, the learning path, the API
and the package all read bundles through it. Do not re-derive bundle order
anywhere else.

### Invariants worth knowing before you edit

- **A bundle is derived, never stored.** There is no bundle table.
- **A version supplied by a PDF stores no copied text** — its text *is* its
  objects. Only *generated* versions live in `LessonVariant`, one row per
  object of the Normal bundle. Anything that counts `LessonVariant` rows to
  decide whether a version exists is wrong; ask `version_bundles(group)`.
- **Version roles live on the group**, in `version_selection`:
  `normal_material_id`, `bundle_roles`, `bundle_roles_assigned_by`
  (`teacher` / `llm_validated` / `heuristic` / `displaced_by_teacher`),
  `bundle_roles_decided_at`, `label_locked`, `auto_label`.
- **Teacher decisions are never overwritten.** A rejected suggestion, a locked
  label, a teacher-provenance role: automatic paths must skip them. Several
  bugs in this area have already been found and fixed; treat it as a hard rule.
- **A concept takes its bundle's heading as its name only when that bundle
  holds 2+ objects**; a single-object bundle keeps its own title. (Real data:
  Solid, Liquid and Gas all sit under a heading called "Matter" — the heading
  rule would name three concepts "Matter" and the criteria's same-name veto
  would delete their edges.) Implemented as `concept_bundles.bundle_label`.
- **`represented_by` means "taught through another object"**, and every
  consumer filters `represented_by__isnull=True`. A dangling pointer therefore
  makes content vanish silently from the lesson, the audio and the package.
  `place_unit` and the move endpoints release companions for this reason.

### How bundles form

1. **Runs inside a PDF** — consecutive objects sharing a section heading
   (`unit_matching.find_units`).
2. **Corroboration from another PDF** — a run only becomes one concept when
   another PDF names it with a matching heading or title. Structure alone
   over-merges; scores alone are useless here (measured: the cross-encoder
   scores nearly everything 0.5–0.65 against everything).
3. **Apply or ask** — at or above the auto threshold (0.6) with margin, the
   objects are placed automatically; between the review threshold (0.3) and
   0.6 a suggestion card is raised for the teacher.
4. **Images need label corroboration to group automatically** (added
   2026-09-21). Two AI-written figure descriptions share stock phrasing and
   scored 0.6+ against each other regardless of subject; three separate wrong
   figure pairings came from this.

### Teacher controls

In the topic review screen ("Review Connections"): **Move out**, **Move to…**,
**↑**, **↓** per object, plus the older **Connect** and **Separate**. Plain
buttons, `aria-label`s naming the object and its file, `aria-disabled` rather
than `disabled` (so the control stays in the tab order), and a focus-restore
ref so a screen-reader user is not dropped at the top of the page after every
press. Keep those properties if you touch that UI.

## 4. The learning path

`backend/learning_path/` derives a prerequisite graph over concepts, then
orders it with Kahn's algorithm. The thesis commits to three criteria and a
vote (3/3 = accepted, 2/3 = pending, otherwise nothing), each traceable to
manuscript §2.6: Wang et al. 2016 (document position), Liang et al. 2015
(RefD reference), Aytekin & Saygin 2024 / all-MiniLM-L6-v2 (embeddings).
Keep that structure; measurement changes are allowed if documented.

- **Temporal order** — position in the merged document order.
- **Semantic reference (RefD-style)** — a concept's *key terms* are its name
  plus the distinctive terms it introduces (a term belongs to the earliest
  concept that uses it; terms used by too many concepts are dropped). `ref(B→A)`
  is the weighted share of A's key terms that B's text uses. Also counts a
  **head-word mention** ("seed" for "seed formation") and **section
  containment** (B sits under a heading named A).
- **Foundationality** — inbound/outbound ratio over the same reference scores.
- Examples-type concepts take part in no pair and are ordered last; the
  contrast veto covers "unlike", "while", "than" and friends; there is no
  cross-section cap.
- Constants (calibrated 2026-09-17, documented in
  `docs/learning_path_revision_2026-09-17.md`): `REF_MAX_DF_RATIO = 0.34`,
  `REF_MARGIN = 0.0`, `PHRASE_COSINE = 0.80`, `MIN_IOL_MARGIN = 0.25`.

### The gold standard — treat this as the acceptance test

The teacher hand-specified the correct edges and order for two real lessons.
They live in `backend/learning_path/fixtures/gold_map_*.json` (the map) and
`gold_topic_*.json` (real lesson text), and `learning_path/test_gold_paths.py`
runs the **real** sentence encoder against them.

Current, and **must not regress**:

| Topic | Required edges accepted | Forbidden | Order |
|---|---|---|---|
| 62 Solid, Liquid and Gas | 10 / 10 | 0 | matches |
| 79 Reproduction Among Flowering Plants | 4 / 8 | 0 | matches |

The four missing topic-79 edges are recorded in the fixtures as
`known_missing`, so the test fails on a **new** gap, a forbidden edge, a wrong
order, *or* a gap that closes (which means the list needs updating). The gaps:
stamen→pollination and pistil→pollination come out pending (teacher-approvable);
pollination→fertilization and fertilization→seed are not proposed at all.
Causes: the linking words (pollen, anther, stigma) are used by too many
concepts to count as distinctive, and there is no stemming, so "fertilized"
never matches "fertilization".

**Do not tune constants to close those gaps.** They were deliberately left
after two calibration runs stopped; the constants are already fitted to these
two lessons only, and a third lesson is what the project needs before more
tuning is defensible.

## 5. What changed recently, and why

Chronologically, all on `jean-latest`:

1. **2026-09-17 — grouping merges + revised learning-path criteria**
   (spec `docs/superpowers/specs/2026-09-17-grouping-merge-and-learning-path-design.md`).
   Fixed: duplicate/fragment concepts (23 → 7 on one topic), a summary table
   that collected 13 wrong edges, reversed comparison edges, numbered labels
   escaping the structural check, uploaded PDFs never deleted from disk
   (436 orphans → 0). Introduced the RefD key-term reference, head-word
   mentions and section containment. Before/after: 0/10 and 1/8 → 10/10 and 4/8.
2. **2026-09-20 — concept bundles** (spec
   `docs/superpowers/specs/2026-09-20-concept-bundles-design.md`, plan
   `docs/superpowers/plans/2026-09-20-concept-bundles.md`). The manual merge
   step was removed entirely and replaced by automatic bundling. The merge-era
   code is preserved on branch **`current-with-merge-function`** (pushed to
   origin) if you ever need to compare.
3. **2026-09-21 — fixes from a real teacher run-through**: concept names
   (single-object bundles keep their own title), overlapping row controls,
   images needing label corroboration, and the figure-description prompt
   rewritten as ROLE / TASK / CONTEXT / FORMAT.

### Things that were found the hard way (don't reintroduce them)

- Retiring the PDF-supplied `LessonVariant` rows broke **two consumers outside
  the diff**: the publish completeness gate (a two-PDF topic could not publish
  at all) and audio generation (a PDF-supplied version shipped **silent**).
  Both are fixed; both were invisible to a passing test suite because the
  existing publish test mocked the middle and used one PDF.
- A deterministic "strip the model's chatter" helper deleted real sentences
  (it partitioned on the first colon in the whole text). It now only strips a
  leading interjection or a recognised meta clause inside the first sentence.
  **Under-reach is acceptable here; over-reach is not.**
- A repair script recorded its own splits as *teacher* decisions. Those rows
  were deleted. Never write `teacher_reviewed` from a batch job.

## 8. Conventions

- **Work is specced before it is built.** Designs live in
  `docs/superpowers/specs/`, implementation plans in `docs/superpowers/plans/`.
  Read the newest spec before changing grouping, versions or the learning path.
- **Never stage** `backend/course/tests.py` or `backend/course/variant_generator.py`
  without checking — the user keeps uncommitted work there — and never commit
  `frontend/dist/*` except as a deliberate rebuild, or `MAVIA MANUSCRIPT.docx`.
- Use explicit `git add <path>`; do not `git add -A`.
- Commit messages end with a blank line then the co-author line the session is
  told to use.
- Run the full backend suite before committing anything that touches grouping,
  versions, publishing or the path. `test_gold_paths.py` is slow (real model)
  but is the one test that says whether the learning path still works.
- Log what you did in `docs/AGENT_LOG.md`.
